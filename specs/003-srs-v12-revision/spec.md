# Feature Specification: SRS V1.2 核验整改

日期：2026-10-07。状态：拟定实施规格。用户要求按照需求工程核验结果重新修改 SRS。

## User Scenarios & Testing

### User Story 1 - 开发人员独立实施 (P1)

开发人员只阅读 SRS，即可确定业务请求、管理员认证、首次基准纠错、交换摘要、监控与保留规则。

验收：U01至U10的决定写入规则及对应验收；无需查阅工作说明书或核验报告补齐实施规则。

### User Story 2 - 使用者确认需求方向 (P1)

读者可区分缺样本、真实零和零分母，确认筛选何时生效，并按实际配置判断交付。

验收：I01至I03写入界面规则及验收；交互演示修正分析条件提前生效，其余正式后台要求标明演示边界。

## Requirements

- FR-001：用SRS V1.2正文及AC覆盖13项问题，保持FR/NFR/IF/TP编号稳定。
- FR-002：定义最小业务API契约、确定性JSON摘要与中文及转义黄金样例。
- FR-003：规定认证初始化与恢复、限流、首次基准纠错、联系保留生命周期和监控语义。
- FR-004：补足正常负载成功率、已正式提交标记、多修订回退、参数化验收和分析应用时机。
- FR-005：同步Typst、入口及原型边界；修正分析条件交互，编译并复查实际结果。
- FR-006：源文件入Git，不恢复CI/钩子/检查清单，不实现正式后台，不把文档整改当成运行验收。

## Success Criteria

- SC-001：13项问题均有规则、验收及修订记录，无规则互相矛盾。
- SC-002：28项FR、11项NFR、4项IF及12项TP编号齐全，Typst可编译。
- SC-003：黄金样例由Python和JavaScript计算得到相同UTF-8字节摘要；分析未应用、非法条件不改变结果，合法应用后同步。
- SC-004：仅源文件提交；正式认证/压测/实际交换等未实施能力明确留作开发验收。

## 暂时性实施规划

采用核验报告建议为起点，具体取值由本次SRS确定。首次基准仅在唯一首期退回且从未省审通过时可受控更正。其余历史错值走独立修订。默认配置验收与合法非默认配置验收同时定义。保留开发人员主导和现有单体技术方案。
