# Feature Specification: SRS 需求工程全流程核验

**Feature Branch**: `codex/srs-engineering-audit`
**Created**: 2026-10-07
**Status**: 审查交付完成；SRS结论为需修订后复核（2026-10-07）
**Input**: 现在用 speckit 对 SRS 进行一次需求工程的全流程核验。

## User Scenarios & Testing

### User Story 1 - 判断整份需求是否完整且可执行 (Priority: P1)

新加入的开发人员能够查看审查结论、全部需求库存、跨章节问题及明确的修正建议，
判断 SRS 是否适合作为开发基线，而不是将局部原型验证误认为全部需求通过。

**Why this priority**: 整份 SRS 的开发准备度是此次核验目标。
**Independent Test**: 逐项检查所有 FR/NFR/IF 都有对应验收、审查状态、证据位置与建议。

**Acceptance Scenarios**:

1. **Given** 当前完整 SRS 与工作说明书，**When** 做范围和字段核对，
   **Then** 每类功能、必要字段、角色、状态及原始业务要求均有明确覆盖结论。
2. **Given** 规则横跨状态、字段、接口及配置章节，**When** 做一致性审查，
   **Then** 问题包含稳定编号、严重级别、位置、影响和开发人员可执行的拟定方案。
3. **Given** 存在外部协议及生产能力未实现，**When** 汇总结果，
   **Then** 需求准备度、原型演示证据和正式交付验收状态分别说明。

### User Story 2 - 根据证据复查并安排整改 (Priority: P1)

开发人员能够复现审查中的关键反例、找到验收缺口，并按优先级安排修订。

**Why this priority**: 结论必须有证据，避免只有泛化的“建议完善”。
**Independent Test**: 按报告复核字段校验、统计答案、缺样本、摘要和文档同步结果。

**Acceptance Scenarios**:

1. **Given** 原型、作者源和 Typst 源，**When** 检查一致性及受影响交互，
   **Then** 记录实际执行范围、结果、产物位置，不把未执行的生产验收标为通过。
2. **Given** 审查发现问题，**When** 形成整改规划，
   **Then** 每项有完成条件，范围以开发工作为主，不附加跨部门签字流程。

### Edge Cases

- 拥有需求编号和验收组仅证明关联存在，不证明验收已经执行。
- 同一需求分布在正文、暂时性实施规划、原型及历史报告时，按版本分别解释。
- 真实国家接口输入缺失不能用模拟成功代替。
- 不修改只读分析阶段的业务源文件，也不自动扩大为正式后台开发。

## Requirements

### Functional Requirements

- **FR-001**: 核对当前 SRS 全文及工作说明书范围，验证企业字段、减少字典、13 条查询条件和各角色核心流程。
- **FR-002**: 建立全部 FR/NFR/IF 的独立库存，关联验收组、审查任务和当前证据状态，不遗漏编号。
- **FR-003**: 对角色授权、数据状态、版本、快照、窗口、修订、统计、通知及删除规则做交叉一致性分析。
- **FR-004**: 审查性能、安全、恢复、兼容、接口、配置、外部依赖及验收是否可测，区分暂定决策与实际完成。
- **FR-005**: 为发现的问题提供编号、类别、严重级别、具体位置、影响和暂时性实施规划及完成条件。
- **FR-006**: 验证作者源与 Typst 源同步、文档可编译，复核相关原型规则并记录实际结果。
- **FR-007**: 输出完整核验报告，说明需求准备度、原型边界、未执行正式验收和整改顺序。
- **FR-008**: 遵守轻量仓库约定；工具临时脚本、提取文本及 PDF 不上传，不新增 CI、提交钩子或检查清单。

### Key Entities

- **需求库存项**：需求编号、主题、SRS 位置、验收关联、核验任务及审查状态。
- **发现项**：问题编号、严重级别、证据、影响和建议完成条件。
- **证据**：明确输入版本和实际执行范围的文档、代码或运行结果。

## Success Criteria

### Measurable Outcomes

- **SC-001**: FR-01 至 28、NFR-01 至 11、IF-01 至 04 共 43 个需求编号全部纳入库存并关联核验任务与验收组。
- **SC-002**: AC-01 至 14、AC-10A/B 及 TP-01 至 12 全部检查，无未说明的编号遗漏；不以编号存在计算实际测试通过率。
- **SC-003**: 每个发现项均包含位置、影响、拟定解决方案及完成条件，所有正式验收未执行项明确标记。
- **SC-004**: 报告可据其记录复查文档同步、编译和选定原型验证；没有产物或真实凭据进入提交。

## Assumptions

当前作者源与 SRS V1.1 Typst 源为审查基线，工作说明书用于范围核对。
此次“全流程”指需求工程的整理、澄清、规划、追踪、分析、证据核验和收敛，
不表示已开发或验收完整生产系统。

## 暂时性实施规划

沿用既定业务范围，不因审查引入新部门工作。问题的拟定方案写入报告，
本轮保持 SRS V1.1 和原型业务源不变，避免将只读核验变成未经说明的业务规则修改。
核验产出独立报告及本目录规格、计划、任务；现有项目约定已适用，无需新版本。

## 规格审阅

已核对范围、两项用户故事、八项审查要求和四项成功标准。
用户历史偏好已明确，无需再询问常规技术选择；业务歧义留拟定方案，
不冒充已获业务确认。质量审阅在对话内进行，不创建检查清单文件。
