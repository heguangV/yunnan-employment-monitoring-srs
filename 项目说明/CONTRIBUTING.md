# 源文件维护与 Git 约定

本目录是独立 Git 仓库，默认分支为 `main`。维护范围是当前需求源、原型、共享样式、说明及必要开发配置。业务文件按 `AGENTS.md` 的收纳规则保存，根目录只保留必须位于此处的配置文件。

## 日常工作

1. 从需要继续的分支新建工作分支，建议 `codex/<主题>`。
2. 修改需求作者源或原型；需求调整同步文档源、页面映射和说明，用浏览器体验受影响的交互。
3. 明确添加文件后检查暂存内容：`git diff --cached --stat` 和 `git diff --cached`。
4. 使用描述结果的提交说明，再按用户要求提交或推送。

不要使用 `git add -f` 将被忽略的产物加入 Git。禁止提交口令、访问令牌、真实企业资料和本机依赖路径；共享分支不使用强制推送。

## 功能规格

使用 Spec Kit 时先读 [AGENTS.md](../AGENTS.md) 和 [constitution.md](../.specify/memory/constitution.md)。每项实际行为变化在 `specs/NNN-主题/` 中维护规格、计划和任务三份文档，相关决策及实际浏览器验收结果合并进计划。普通文字或目录收纳调整可直接修改。

官方技能、模板和工作流辅助源码作为开发配置保留，Python 命令使用外部运行环境并加 `-B`。不创建项目内虚拟环境，不新增 CI、钩子、格式检查或检查清单文件。

## 文档与交付文件

`需求文档/需求规格书内容.md` 是需求作者源，当前 Typst 源和 PDF 位于同一文件夹。修改需求时同步两份可编辑源；编译方法见 [README.md](README.md)。所有独立 Typst 文档引用 `styles/bit-format.typ`。

Excel 与 Project 放在 `项目计划/`，课程素材放在 `课程资料/`，原型源码及使用说明放在 `项目交互原型/`。必要的课件图片是课程目标资料，应与检查截图区分。

临时生成脚本、审核脚本、检查截图、渲染预览、缓存、工具依赖、旧草稿和重复导出只能位于项目外的临时目录。交付前将确认的目标文件收纳到对应文件夹，并把过程文件移出项目；不能只用 `.gitignore` 隐藏它们。

`.gitattributes` 将文本规范为 LF。原型的较长函数不会仅为调整格式而整体重排，功能变更保持可审阅。
